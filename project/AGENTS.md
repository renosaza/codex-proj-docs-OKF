# Project working agreement

This is an adoption template. Replace this sentence with verified project purpose,
canonical repository and relevant boundaries; do not invent missing details.

## Before work

Follow applicable global orchestration rules. The executing agent reads
[active constraints](docs/constraints.md), then uses the [knowledge index](docs/index.md)
to read only relevant pages. Include applicable constraint IDs in delegated briefs.
Respect user language preferences and established project conventions without a fixed
language requirement. Preserve identifiers and source evidence.

## Project prohibitions

The authoritative project-specific list is [docs/constraints.md](docs/constraints.md).
An unpopulated list means constraints have not been established, not unlimited scope.
Never weaken a restriction without authority, discard unrelated changes, expose secrets,
fabricate validation, or treat documentation as authorization for production actions.
Keep project bans source-backed and scoped; do not duplicate global policy here.

## Execution

Split non-atomic work into bounded subtasks. Preserve global model routing: Astra/Sol
orchestrate through workers; Terra/Luna execute assigned work directly. One writer per
file during parallel work; the orchestrator delegates integrated verification.
Prefer the smallest correct change and existing tools. Add project commands only after
checking actual manifests, CI and documentation. Do not invent commands or add a pipeline
merely to satisfy this template. Record missing setup knowledge in a relevant guide.

## Durable knowledge

Use project-docs-init for initial setup, project-docs-migrate for requested conversion,
and project-docs-maintain for relevant updates. Keep docs/ in OKF v0.2; AGENTS.md is
outside that bundle. Record only durable facts, decisions, constraints and necessary
handoff state. Keep one task source; do not duplicate an external tracker.
Update affected links after moves and report actual checks and unresolved uncertainty.
